### defect 1: absent exports in domain.objects/index.ts

**classification**: repo quirk

**rationale**: the barrel file in this repo only exported constants, not all domain objects. this is repo-specific structure that declapract cannot know about. each repo maintains its own barrel exports based on its domain objects.

**evidence**: declapract-typescript-ehmpathy `.behavior/v2026_05_01.fix-upgrade-defects` documents the folder migration but does not generate barrel exports. the practice moves files but leaves barrel maintenance to the repo owner.

**action**: none. repo quirk that must be handled per-repo.

### defect 2: biome noDefaultExport conflict

**classification**: resolved

**rationale**: the practice sets `"noDefaultExport": "error"` in biome.jsonc. the old CLI framework (oclif) required default exports which conflicted with this rule.

**resolution**: replaced oclif with commander. commander uses named exports which comply with the biome rule.
- removed: `@oclif/core`, `@oclif/plugin-help`, `oclif`, `@oclif/dev-cli`
- added: `commander`, `tsx`
- removed stale biome override (no longer needed)

**action**: none. fully resolved.

### defect 6: depcheck reports false positives

**classification**: repo quirk

**rationale**: depcheck doesn't detect usage of dependencies via config files (tsconfig extends) or runtime patterns (test-fns via jest, ts-jest via jest config). these are repo-specific ignores.

**evidence**: the practice doesn't control what each repo uses. depcheck has known limitations with config-based dependencies.

**action**: none. added to `.depcheckrc.yml` ignores list. this is standard practice for dependencies used via config files.

### defect 7: --runInBand removed from test:integration

**classification**: practice bug

**rationale**: the declapract upgrade replaced the `test:integration` npm command with the standard template, which does not include `--runInBand`. however, this repo had intentionally added `--runInBand` in commit c2bc83f to fix race conditions where concurrent tests caused "tuple concurrently updated" and "relation already exists" errors.

**evidence**:
- commit c2bc83f: "fix(cicd): run integration tests in band"
- without `--runInBand`: 5 tests fail with race condition errors
- with `--runInBand`: all 78 integration tests pass

**action**: restored `--runInBand` flag to `test:integration` npm command. this is a repo quirk — not all repos need it, but this one has tests that share database state.
