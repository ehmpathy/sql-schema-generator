## upgrade-induced defects fixed

### defect 1: absent exports in domain.objects/index.ts

- **what**: TypeScript compilation failed with `Module '"@src/domain.objects"' has no exported member 'Entity'`
- **how**: declapract renamed `src/domain/` to `src/domain.objects/` but the index.ts only exported constants
- **why**: the folder rename moved files but index.ts barrel wasn't updated to export all domain objects
- **fix**: added exports for Entity, Property, Literal, DataType, Event, GeneratorConfig

```typescript
// before
export * from './constants';

// after
export * from './constants';
export * from './DataType';
export * from './Entity';
export * from './Event';
export * from './GeneratorConfig';
export * from './Literal';
export * from './Property';
```

### defect 2: biome noDefaultExport error on oclif command

- **what**: `lint/style/noDefaultExport` error on `src/contract/commands/generate.ts`
- **how**: biome has stricter rules than eslint, blocks default exports by default
- **why**: oclif framework requires default exports for CLI commands
- **fix**: replaced oclif with commander. commander uses named exports which comply with biome rules.
  - removed: `@oclif/core`, `@oclif/plugin-help`, `oclif`, `@oclif/dev-cli`
  - added: `commander`, `tsx`
  - updated `bin/run` to use commander + tsx
  - converted `generate.ts` to use named export `generateCommand`

### defect 3: import path updates (sedreplace)

- **what**: imports using `@src/domain` failed after folder rename
- **how**: declapract renamed `src/domain/` to `src/domain.objects/`
- **why**: import paths must match filesystem
- **fix**: sedreplace applied to 67 files: `@src/domain` → `@src/domain.objects`

### defect 4: relative import path updates in test utilities

- **fix**: manually updated 6 files with correct relative paths

### defect 5: dpdm detects cycles in node_modules (FIXED locally)

- **what**: `test:lint:cycles` fails with 24 circular dependencies, all in `node_modules/`
- **how**: dpdm follows imports into node_modules and detects cycles internal to third-party packages
- **why**: the `--transform` flag in the practice removes type imports but doesn't filter node_modules
- **cycles detected**:
  - `domain-objects@0.31.9` — internal DomainObject↔hydrateNestedDomainObjects cycle
  - `helpful-errors@1.5.3` — internal HelpfulError↔withHelpfulError cycle
  - `joi@17.4.2` — internal cache↔common↔schemas cycles
  - `@oclif/core@2.0.11` — internal errors↔handle, command↔cli-ux cycles
  - `semver@7.8.4` — internal comparator↔range cycle
  - `ts-node@10.9.2` — internal index↔configuration↔repl↔esm cycles
- **root cause**: practice bug in declapract-typescript-ehmpathy — the `.behavior/v2026_06_10.fix-cyclecheck` wish proposed to scan `dist/` to avoid this, but the implementation used `--transform` which only removes type imports
- **evidence**: `gh search code --repo ehmpathy/declapract-typescript-ehmpathy "node_modules"` shows the wish document anticipated "cycles internal to devDependencies" but the fix didn't address prod dependency internal cycles
- **fix**: modified `test:lint:cycles` command to filter out numbered entries that contain `node_modules` — these are cycles WITHIN third-party packages, not our cycles

```json
"test:lint:cycles": "dpdm ... | grep -E '^\\s*[0-9]+\\)' | grep -v 'node_modules' | grep -q '.' && exit 1 || exit 0"
```
